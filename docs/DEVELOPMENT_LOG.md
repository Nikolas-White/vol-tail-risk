# Development log

Things that broke, surprised me, or did not work while building this project, in
the order they happened. Kept deliberately: a model-validation reviewer wants to
see what was tried and caught, not just the final state. The "What didn't work"
section of the README and the validation report draw from this file.

| # | Phase | What happened | Root cause | Fix / decision |
|---|-------|---------------|-----------|----------------|
| 1 | Data | Yahoo Finance, Stooq and FRED were all unreachable from the sandbox the project was built in (HTTP 403 at the proxy). | Network policy of the build environment, not the code. | Wrote the whole pipeline against the cached-parquet schema, added a synthetic GJR-GARCH-t data generator for an end-to-end dry run, and made real-data numbers auto-fill when `make all` is run with internet access (locally or in the `full_backtest` GitHub Action). No real-market number in the docs was typed by hand. |
| 2 | Models | First no-lookahead test run **failed** for EGARCH: 5-day variance forecasts on dates *before* the perturbation differed between two runs. | Not lookahead: `arch`'s `forecast(method="simulation", random_state=...)` ignores `random_state` for the innovation draws and uses the distribution's own unseeded generator, so every run was different. | Pass an explicitly seeded `rng` sampler (seed = config seed + hash(asset, refit date, model)). Reruns are now bit-for-bit identical and the test passes. The perturbation test was written to catch leakage; it also catches non-determinism, which is a good reason to keep it strict (`rtol=1e-10`). |
| 3 | Models | `arch` returns read-only NumPy views from `forecast().variance`. | Library behaviour. | `.copy()` before overwriting the 1-step EGARCH column with the exact analytic value. |
| 4 | Models | Noted while reading `arch` source: forecast variance *bounds* are computed from the full residual series passed in (max squared residual). | Library design; bounds are ~1e6x typical variance so they never bind in practice. | We only ever pass data up to the block's last origin, and the perturbation test would fail if a bound ever bound on a future value. Documented in METHODOLOGY.md. |
| 5 | Evaluation | The Mincer-Zarnowitz unit test failed on its first run (slope 0.83 vs 1 on an unbiased forecast). | Not a code bug: with an r^2-style proxy (chi-square noise) and n = 4,000 the slope's standard error is ~0.07, so 0.83 is a 2.3-SE draw. The *test* was underpowered and used an arbitrary tolerance. | Raised n to 40,000 and replaced the fixed tolerance with "within 3 standard errors"; the biased-forecast case must still be rejected at p < 0.001. Stricter, not weaker. Lesson that carries over to the real results: MZ regressions on r^2 have very low R^2 and wide intervals by construction. |
| 6 | Dashboard | The Streamlit smoke test crashed when `VOLTAIL_CONFIG` was set to an empty string. | `load_config` treated `""` as a file path. | Empty env var now means "use defaults"; config paths are also resolved relative to the repo root so the CLI works from any directory. |
| 7 | Docker | `docker build` could not pull `python:3.13-slim` in the build sandbox (Docker Hub, GHCR, ECR and the GCR mirror all blocked). | Network policy of the sandbox. | Verified the image contents another way: copied exactly the files the Dockerfile `COPY`s into a clean virtualenv, installed `requirements.lock`, ran uvicorn and Streamlit from that layout and hit `/health`, `/forecast/SPX`, a 404 path and `/docs`. The real `docker build` + container smoke test runs in the `docker` job of `.github/workflows/ci.yml`. |
| 8 | Report | First synthetic report picked Bitcoin as the "focus" asset for the headline figures. | Forecast files were loaded in alphabetical order. | Load in config order (S&P 500 first). |
| 9 | Report | First headline sentence said the best model "cannot be separated from 3 others on every asset", which was wrong when the best model itself was outside the MCS for one asset. | Sloppy wording generated from correct numbers. | Headline now states the leader's own MCS count and lists separately the models that are inside the MCS on every asset. |
| 10 | Data (real) | First cleaning of the real data dropped **12 and 13 March 2020 for the S&P 500 and 13 March 2020 for the TSX** as "bad ticks". Those are genuine COVID crash days (-10.0% then +8.9%). | The spike filter scaled moves by the median absolute return of the previous **250** days. After a calm 2019 a genuine 10% whipsaw looked like a 20-SD print. | Scale now uses the previous **20** days (it adapts to crises) with an 8-SD threshold. On the real data it now flags only five EUR/USD prints in 2008, all dated on the 8th of a month (5-16% one-day moves that fully reverse, a likely day/month parsing error at the source). A new test keeps crisis whipsaws. Lesson: cleaning rules need to be checked against the events they could delete. |
| 11 | Data (real) | `yfinance` and every other market-data host were blocked from both the cloud sandbox and the desktop VM. | Network egress policy. | Fetched the same Yahoo Finance data (chart API v8, the endpoint yfinance itself uses) in the Claude desktop app's browser, applied the yfinance `auto_adjust` rule (OHLC x adjclose/close), saved CSVs and loaded them with `scripts/download_data.py --from-csv`. Today's still-forming bar and duplicate FX dates are dropped and recorded in `data/raw/manifest.json`. |
| 12 | Data (real) | The first real-data report showed the Garman-Klass range proxy averaging 1.8x (EUR/USD) and 3.2x (GBP/USD) the squared return, and HAR/XGBoost doing badly on GBP/USD. | One bad print: on 2012-01-27 both FX feeds report a daily *low* of 0.76 / 0.64 (a 42-59% wick) while open and close are normal. That single day contributed most of the GK variance for the whole sample (top 1% of days = 53-73% of the GK sum). | Added a past-only "bad wick" check: a range more than 25x the median range of the previous 20 days is marked unusable. Genuine extremes in the data peak at ~14x (2010 flash crash, Brexit, COVID, Bitcoin); the bad prints are 65x and 163x. After the fix GK/r^2 is 0.94 and 1.02 for the FX pairs, as expected for 24-hour markets. Lesson: one garbage print can dominate a variance-based statistic, so check contributions, not just averages. |
| 13 | Scope | After the first real-data run the project looked too broad to defend in an interview (16 models, a dashboard). | Breadth for its own sake. | Trimmed to 13 models: removed the 63-day rolling SD, 500-day HS, EGARCH-normal and unconditional EVT (each duplicated a model already in the set), and the Streamlit dashboard (the API covers serving). Added one *focused* extension instead: a pre-registered test of whether skewed-t innovations fix the equity VaR failures (METHODOLOGY section 9). |
| 14 | Research | The pre-registered follow-up H2 (skewed-t filter for FHS/EVT) came out **PARTIALLY SUPPORTED** on real data, but the synthetic placebo, where H2 is false by construction, returned the **same** verdict with the same pattern (2 cells significantly better, 0 worse, per pair). | My decision rule was too lenient: criterion E2 counts one-sided 5% tests across 14 cells with no multiple-testing correction, so 1-2 "significant" cells are expected by chance. | Kept the pre-registered verdict as written (changing the rule after seeing the result would defeat pre-registration), and added an automatic placebo comparison to the report that states H2 is not established. Lesson: run the decision rule on placebo data *before* registering it. H1 does not have this problem: its placebo returns NOT SUPPORTED. |
